# Ordella Beta — Roadmap Preview

What beta participants see of the product roadmap, what remains hidden, and how feedback influences planning. Ordella follows **honest labeling** for preview and beta modules per [brand voice](../brand/VOICE_AND_TONE.md) and [changelog](../docs/public/changelog.md).

## What beta users will see

### Public and beta-shared visibility

Beta participants receive:

- **Public documentation** on [docs.ordella.com](https://docs.ordella.com)—including systems pages, architecture, integration guides, and expanding [API reference](../docs/public/api-reference.md).  
- **Beta changelog** section in weekly newsletters—fixes, known issues, breaking change notices with migration notes.  
- **Roadmap preview board** (placeholder tool)—quarterly themes, not commit-level dates: e.g., “Webhook replay,” “Additional Genome features,” “Marketplace GA.”  
- **Preview modules** explicitly labeled in docs and portal: AI Assistant expansions, Autonomous Engine policies, Digital Twins simulation, advanced Orchestration—aligned with [systems overview](../docs/public/systems/overview.md).  
- **Monthly roadmap AMA** (30 min) for accepted cohort—recordings NDA for beta community only.

### Typical preview themes (placeholder)

| Theme | Beta visibility | Doc anchor |

| Developer Portal polish | Iterative releases | [Developer Portal](../developer-portal/README.md) |

Beta users see **direction** and **priority themes**; they do not receive binding delivery dates for GA.

## What is hidden

The following stay **internal** or **executive-only** until public announcement:

- Unannounced acquisitions, pricing finalization, and exact GA calendar date  
- Unreleased endpoint shapes not yet in docs (no “secret APIs” for beta without NDA addendum)  
- Customer-specific commercial terms and other participants’ pilot data  
- Security vulnerabilities before coordinated disclosure  
- Headcount, fundraising, and detailed financial projections  

Participants under **beta NDA** (placeholder agreement) may see **slide-level roadmap** one quarter ahead—still not a contract to ship.

If a capability is not in public or beta-shared docs, assume it is **not available**—do not build dependencies on verbal promises from office hours.

## How roadmap feedback is handled

### Intake

Feature requests use [FEEDBACK_LOOP.md — Feature request workflow](./FEEDBACK_LOOP.md#feature-request-workflow) with category `feat`. Roadmap AMA questions are logged with votes.

### Product review rhythm

- **Weekly:** Triage new requests; link duplicates.  
- **Monthly:** Prioritization against platform pillars ([Messaging Pillars](../brand/MESSAGING_PILLARS.md)): unification, real-time, API-first, intelligence, global scale.  
- **Quarterly:** Refresh beta roadmap preview board; communicate changes in [COMMUNICATION_PLAN.md](./COMMUNICATION_PLAN.md) newsletter.

### Outcomes participants receive

| Decision | Communication |
|----------|----------------|
| **Planned (beta)** | Added to preview board; may invite design partner |
| **Planned (post-GA)** | Deferred with rationale |
| **Not planned** | Declined with reason (scope, security, strategy) |
| **Shipped** | Changelog + newsletter credit when reporter opted in |

Feedback **heavily influences** documentation and API ergonomics; it **informs but does not dictate** GA scope. Security and tenancy work preempts feature votes.

### Relationship to public roadmap

After GA, themes graduate to public [changelog](../docs/public/changelog.md) and optional public roadmap page on **ordella.com**—beta preview board archived or anonymized.

## Participant responsibilities

- Do not share NDA roadmap slides externally.  
- Label demos “Preview” when showing unreleased UI ([Imagery guidelines](../brand/IMAGERY_GUIDELINES.md)).  
- Vote and comment constructively—outcomes are inputs, not guarantees.
