## 24-hour plan (L+1)

1. **09:00** — Hot wash (60 min): incidents, metrics, doc gaps ([MONITORING](./MONITORING_AND_RESPONSE.md) EOD template).  
2. **10:00** — Publish changelog fixes for any L-day doc errors.  
3. **12:00** — Social thank-you + developer tip post.  
4. **14:00** — Partner office hours.  
5. **EOD** — P0/P1 ticket zero goal; beta feedback triaged.

---

## 72-hour plan (L+3)

1. Developer drip email #2 (webhooks).  
2. Press follow-up pitches (second-wave outlets).  
3. Retailer outbound to inbound demos (sales).  
4. Review API error logs; patch top doc confusion.  
5. Comms: one [LINKEDIN_PRODUCT](../social/LINKEDIN_PRODUCT_HIGHLIGHTS.md) post.

---

## 7-day plan (L+7)

1. **Weekly beta newsletter** ([beta COMMUNICATION](../../beta-program/COMMUNICATION_PLAN.md)).  
2. **Developer webinar** — live [onboarding](../../developer-onboarding/OVERVIEW.md) demo.  
3. **Launch metrics report** to leadership vs [LAUNCH_OVERVIEW](../timeline/LAUNCH_OVERVIEW.md).  
4. **Retro doc** — update [ASSET_STATUS](../timeline/ASSET_STATUS.md); [CHECKLIST](../timeline/CHECKLIST.md) lessons.  
5. **Social** — week-in-review post (approved stats only).  
6. **Partner** — certification workshop; first application decisions.  
7. Plan **D+8–30** per [timeline](../timeline/TIMELINE.md#post-launch-30-day-timeline): Cohort B, case study draft, API reference expansion.
